# 🎱 WASM Ball Bouncing Physics Engine

WebAssembly와 p5.js를 활용한 실시간 공 튀기기 물리 시뮬레이션입니다.

---

## 1. 팀명 / 팀장 / 팀원 이름

- **팀명**: 메테오
- **팀장**: 조민석
- **팀원**: 배성재, 김동민

---

## 2. 프로젝트 개요 및 주요 기능

### 프로젝트 개요
WebAssembly(WASM)와 p5.js를 활용하여 실시간 물리 시뮬레이션을 구현한 프로젝트입니다. C++로 작성된 고성능 물리 엔진을 WASM으로 컴파일하여 웹 브라우저에서 실행하며, p5.js를 통해 시각화하였습니다.

### 주요 기능

- **C++ 물리 엔진**: 고성능 물리 계산을 위해 C++로 작성되고 WASM으로 컴파일
- **p5.js 시각화**: 부드러운 애니메이션과 아름다운 시각 효과
- **실시간 상호작용**: 마우스 클릭으로 공 추가
- **물리 시뮬레이션**:
  - 중력 효과
  - 벽면 충돌
  - 공 간 충돌
  - 에너지 감쇠

### 기술 스택

- **C++**: 물리 엔진 계산 로직
- **WebAssembly**: 고성능 웹 실행
- **Emscripten**: C++를 WASM으로 컴파일
- **p5.js**: 캔버스 기반 그래픽 및 애니메이션
- **HTML5/CSS3**: 사용자 인터페이스

## 3. 실행 방법

### 사전 요구사항

- **Emscripten SDK**: C++를 WASM으로 컴파일하기 위해 필요
- **로컬 웹 서버**: WASM 파일을 로드하기 위해 필요 (Python 또는 Node.js)

### 1단계: Emscripten 설치

```bash
# emsdk 다운로드
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk

# 최신 버전 설치 및 활성화
emsdk install latest
emsdk activate latest

# Windows
emsdk_env.bat

# Linux/Mac
source ./emsdk_env.sh
```

### 2단계: 프로젝트 빌드

#### Windows (PowerShell):
```powershell
.\build.ps1
```

#### Windows (CMD):
```bash
build.bat
```

#### Linux/Mac:
```bash
chmod +x build.sh
./build.sh
```

**참고**: PowerShell에서 `.bat` 파일은 인코딩 문제가 있을 수 있으니 `.ps1` 사용을 권장합니다.

빌드가 성공하면 `physics.js`와 `physics.wasm` 파일이 생성됩니다.

### 3단계: 로컬 서버 실행

#### VSCODE 라이브서버(live server) 실행
-> `http://localhost:5500`

### 4단계: 브라우저에서 실행

브라우저를 열고 `http://localhost:5500` 접속

### 사용법

#### 마우스 조작
- **클릭**: 클릭한 위치에 새로운 공 추가
- **버튼 클릭**: 각 UI에 위치한 버튼 클릭

#### 버튼
- **공 추가**: 랜덤한 위치에 공 하나 추가
- **공 5개 추가**: 랜덤한 위치에 공 5개 순차적으로 추가
- **모두 지우기**: 모든 공 제거
- **중력 ON/OFF**: 중력 효과 토글

#### 키보드 단축키
- **스페이스바**: 랜덤 위치에 공 추가
- **C**: 모든 공 제거
- **G**: 중력 ON/OFF
- **방향키**: 중력 방향 조절
- **M**: wasm모드 js모드 전환
- **B**: 공 500개 추가
- **T**: 벤치마크 그래프 UI 활성화
- **R**: 리셋

## 5. 개발 중 어려웠던 점과 해결 방법

### 어려웠던 점 1: 
기존에 물리엔진 동작기준을 픽셀단위로 동작하게 하였는데 충돌 시 문제나 성능 상의 문제가 많고 프레임단위 계산이 이루어지지 않아 물리엔진이 깨지는 현상이 발생하였습니다.

### 해결 방법: 
단위를 다시 체크하고 픽셀단위를 실제 거리단위로 변형하여 계산하는 로직을 추가하였더니 물리엔진이 다시 정상 동작할 수 있게되었습니다.


### 어려웠던 점 2: 
WASM과 JavaScript 두 엔진을 공정하게 비교하는 벤치마크를 만드는 것이 어려웠습니다. 단순히 실행 시간만 측정하면 WASM 모듈 로딩 시간이나 엔진 전환 시 데이터 동기화 문제로 정확한 비교가 어려웠습니다.

### 해결 방법:
두 엔진의 물리 계산 로직을 완전히 동일하게 구현하고, `performance.now()`를 사용하여 순수 물리 업데이트 시간만 측정하도록 하였습니다. 또한 M 키로 엔진을 전환할 때 공의 위치와 속도를 정확히 동기화하여 동일한 조건에서 비교할 수 있게 만들었습니다.

## 6. (필요한 경우) 가산점 항목에 대한 설명

### 1. 추가 기능 구현
- **중력 방향 조절**: 방향키를 사용하여 중력을 상하좌우로 자유롭게 변경할 수 있습니다.
- **중력 나침반 UI**: 화면 우측 상단에 현재 중력 방향을 시각적으로 보여주는 나침반을 구현했습니다.
- **WASM/JS 모드 전환**: M 키를 눌러 WebAssembly와 JavaScript 물리 엔진을 실시간으로 전환하며 비교할 수 있습니다.

### 2. UI/UX 개선
- **실시간 벤치마크 UI**: T 키로 활성화되는 벤치마크 모드에서 WASM과 JS의 성능을 막대 그래프로 실시간 비교할 수 있습니다.
- **직관적인 정보 표시**: 현재 모드, FPS, 물리 계산 시간, 공 개수 등을 한눈에 볼 수 있는 정보 패널을 제공합니다.
- **키보드 단축키**: 다양한 단축키(M, B, T, R 등)를 제공하여 편리하게 기능을 사용할 수 있습니다.

### 3. 성능 최적화 및 기술 조사
- **Spatial Hash Grid 알고리즘**: 공 간 충돌 감지를 O(N²)에서 O(N)으로 개선하여 대량의 공(500개 이상)도 원활하게 처리합니다.
- **WASM 최적화**: C++ 코드를 `-O3` 플래그로 컴파일하여 최대 성능을 끌어냈습니다.
- **실제 물리 단위 사용**: 픽셀이 아닌 미터, m/s² 등 실제 물리 단위로 계산하여 정확하고 안정적인 시뮬레이션을 구현했습니다.

## 7. Latency 측정 테이블

| 공 개수 | C++ (WASM) | JavaScript |
|---------|------------|------------|
| 500        | <0.3ms           | <0.4ms           |
| 1500        | <0.6ms           | <0.8ms           |
| 5000        | <7.5ms           | <11.3ms           |
| 8000        | <17.0ms           | <29.5ms           |
| 10000        | <24.0ms           | <40.0ms           |
WASM이 JavaScript보다 약 1.3~1.7배 빠르며, 공 개수가 많아질수록 성능 차이가 더 벌어집니다.
